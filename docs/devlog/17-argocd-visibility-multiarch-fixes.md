### 3. ArgoCD Resource Visibility Investigation

**Problem:** User couldn't see Pods, Endpoints, HPA, NetworkPolicy, ScaledObject in ArgoCD UI.

**Root cause:** ArgoCD only tracks resources **defined in Helm chart templates**. Resources created at runtime by the operator or auto-generated by Kubernetes are invisible to ArgoCD.

| Resource | In Helm Chart? | ArgoCD tracks? | Reason |
|----------|---------------|----------------|--------|
| Deployment | Yes | Yes | Defined in template |
| Service | Yes | Yes | Defined in template |
| ServiceMonitor | Yes | Yes | Defined in template |
| CRD | Yes | Yes | Defined in template |
| SA, ClusterRole | Yes | Yes | Defined in template |
| Endpoints | No | No | Auto-generated by K8s for each Service |
| Pods | No | No | Sub-resource of Deployment |
| HPA | No | No | Created by operator at runtime |
| NetworkPolicy | No | No | Created by operator at runtime |
| ScaledObject | No | No | Created by operator at runtime (dynamic client) |

**Attempted fix:** Removed Endpoints/EndpointSlice from ArgoCD `resource.exclusions` config. This didn't work because ArgoCD only discovers resources that are in the Helm chart — removing an exclusion doesn't add new tracked resources.

**Conclusion:** This is a fundamental ArgoCD + operator architecture trade-off. The operator creates resources dynamically (via typed and dynamic clients), outside of Helm's declarative resource set. To see these in ArgoCD would require either:
1. Adding all child resources to the Helm chart (defeats operator purpose)
2. Creating a separate ArgoCD app for Application CRs
3. Using ArgoCD resource tracking annotations on operator-created resources

**Decision:** Accept current behavior. Operator-created resources are visible via `kubectl` and the operator's status subresource.

### 4. Kind Cluster — Single Node

The Kind cluster has only one node (`kind-control-plane`). There are no worker nodes, so the operator runs on the control-plane node. This is normal for Kind. In production (EKS/GKE), separate worker nodes would exist.
